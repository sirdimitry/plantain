# Проверка обновлений Windows

Начиная с 0.1.0-dev.6 приложение один раз при запуске запрашивает публичный GitHub Releases API репозитория sirdimitry/plantain. Проверка идёт после появления окна, ограничена 8 секундами и не блокирует работу. Недоступность сети, лимит GitHub или некорректный ответ не вызывают всплывающих ошибок. Закрытие окна отменяет запрос.

## Окошко обновления

Если есть более новая подходящая версия, появляется небольшое окно с синим заголовком «Вышла новая версия». Оно показывает установленную и новую версии, кнопки «Скачать обновление» и «Позже». Во время активной загрузки и другого диалога предложение откладывается. «Позже» закрывает окно до следующего запуска; постоянной записи этого решения нет.

«Скачать обновление» открывает официальную страницу Windows-релиза в браузере. Пользователь скачивает ZIP, распаковывает его целиком в отдельную папку и запускает новую версию. Автоматической загрузки архива, замены исполняемых файлов и установки в фоне нет; кнопка и текст явно описывают этот порядок. Текущая загрузка не прекращается ради проверки.

## Формат релизов

- Тег Windows: `windows-v0.1.0-dev.6` (в дальнейшем, например, `windows-v0.1.0-dev.7`).
- Архив: `Plantain-0.1.0-dev.6-win-x64.zip`.
- Контрольная сумма: `Plantain-0.1.0-dev.6-win-x64.zip.sha256`.
- Оба вложения должны быть опубликованы, не пусты и иметь статус uploaded. Черновики игнорируются.
- Более новая версия определяется SemVer, включая числовые prerelease-части: dev.10 новее dev.9. Stable-установка не получает preview; preview может получить более новый stable.
- macOS-теги `v1.x` и DMG игнорируются в Windows. Проверка внутри macOS-приложения в этот этап не входит; её будущий формат и DMG рассматриваются отдельно.

Используется список Releases с пагинацией, а не общий releases/latest, который сейчас относится к macOS. Максимум 5 страниц по 100 записей, с общим лимитом времени и ограничением размера ответа. Неполный/неудачный ответ не считается подтверждением актуальности. URL страницы конструируется для этого репозитория, произвольный html_url из ответа не запускается.

## Публикация следующей Windows-версии

После изменения windows/VERSION, README/CHANGELOG, проверок, коммита и отправки ветки:

```powershell
.\windows\scripts\publish.ps1
.\windows\scripts\release.ps1
```

Вторая команда проверяет ZIP/SHA-256 и показывает готовность; она не публикует релиз. Для явной публикации автором:

```powershell
.\windows\scripts\release.ps1 -Publish
```

Скрипт создаёт релиз с префиксом windows-v, ZIP и SHA-256. Предварительная версия помечается prerelease. `--latest=false` сохраняет существующий общий latest для macOS. Для команды нужны авторизованный GitHub CLI и уже отправленный коммит. На этапе 6 публичный Windows-релиз не создавался; сейчас в GitHub есть только macOS-релизы, поэтому обычное окно обновления пока не появляется.

## Приватность и границы

Запросы идут без GitHub-токена, cookies, учётных данных и постоянного кэша. Ссылка Яндекс Диска, папка сохранения и история загрузок не входят в запрос. Страницы GitHub открываются только после нажатия пользователя. Политика Windows обновлена с учётом автоматического API-запроса при запуске.

Проверка доступна в самой версии 0.1.0-dev.6 и новее. Уже скачанные старые версии без этого кода не получают функцию задним числом — первую новую сборку нужно заменить вручную. ZIP и контрольную сумму проверяет пользователь; встроенной установки в этом этапе нет.
