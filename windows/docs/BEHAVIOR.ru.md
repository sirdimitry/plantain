# Поведение загрузчика: контракт Windows

Статус: целевой контракт; реализация движка, защиты и окна этапа 4 — 0.1.0-dev.4, ограничения описаны в [результатах](TEST-RESULTS.ru.md). База: macOS 1.1.1, коммит `acb34baa815265967a81fd6e5a14d2271a5ec5e3`. Источники: [Core.swift](../../Sources/Core.swift), [Privacy.swift](../../Sources/Privacy.swift), [App.swift](../../Sources/App.swift), [CoreTests.swift](../../Tests/CoreTests.swift). Код этих файлов не меняется в рамках переноса.

## 1. Вход и структура результата

- Допускается публичная HTTPS-ссылка на файл или папку: disk.yandex.ru, disk.yandex.com, disk.yandex.com.tr, yadi.sk. Учётные данные в URL и нестандартный порт запрещены. Пробелы по краям ввода удаляются.
- Закрытые ресурсы и вход в аккаунт не поддерживаются. Неверная ссылка или закрытый доступ дают понятное сообщение.
- Корневая папка сохраняется как «Исходное имя copy». Одиночный файл сохраняет имя и расширение, без « copy». Существующая корневая папка переиспользуется для продолжения.
- Вложенные и пустые папки сохраняются. Удалённые пути строятся отдельно от локальных: обратный слеш Windows не должен попадать в путь API.
- Неизвестный тип объекта, отсутствие допустимого размера файла и неполный список папки не превращаются в успешный результат.
- Папки читаются постранично: limit=200, offset, sort=name. Пустая страница до объявленного total — ошибка. Без total чтение продолжается до пустой страницы.

## 2. Проверка имеющихся файлов

- До первого скачивания проверяется весь список уже существующих файлов. Совпавшие сразу входят в «Уже есть», число готовых файлов и готовые байты.
- Требуется совпадение размера; SHA-256 приоритетнее MD5. Хеш сравнивается без учёта регистра шестнадцатеричной записи. Чтение потоковое, отмена доступна во время проверки.
- При отсутствии обеих сумм достаточно размера, но итог явно сообщает количество файлов без контрольной суммы, включая свежескачанные. При частичном успехе число относится к известному списку; отдельные файлы могут оставаться в ошибках.
- Отличающееся содержимое не перезаписывается, не удаляется и не считается готовым. Ошибка одного файла не препятствует обработке остальных допустимых файлов.
- Файл нулевой длины корректен. Если сумма есть, она тоже проверяется.

## 3. Передача и докачка

- Файлы скачиваются последовательно. Содержимое передаётся потоком в .diskloader-partials внутри выбранной папки, без накопления файла целиком в памяти. Размеры и счётчики — 64-битные.
- Техническое имя: SHA-256 от UTF-8 строки «размер\nsha256-или-пусто\nmd5-или-пусто» плюс .part. Исходный URL, его хеш, имя папки и выбранный путь не входят в имя.
- Для безопасной докачки требуется известная контрольная сумма. Без неё старый partial обнуляется через удерживаемый дескриптор перед новой попыткой. Partial большего размера также обнуляется. Это сохраняет запрет использования старых данных без разрыва защиты файла.
- При наличии partial отправляются Range: bytes=offset- и Accept-Encoding: identity. HTTP 206 принимается только при корректном Content-Range: начало равно offset, общий размер соответствует метаданным, конец диапазона допустим. Проверка полного диапазона — усиление относительно строковой проверки Swift.
- HTTP 200 при запросе диапазона означает перезапуск: truncate partial до нуля, запись с начала, без склейки старых и новых байтов.
- HTTP 416 обнуляет непригодный partial через дескриптор и позволяет новой попытке начать сначала. Другие ответы передачи не считаются успешными.
- Запись сверх объявленного размера запрещена. Короткий ответ — незавершённая передача. Готовый partial проверяется по размеру и хешу до публикации.
- При несовпадении хеша partial обнуляется, следующая попытка начинается сначала. Полный partial с верным хешем можно опубликовать без повторного скачивания. Удерживаемый объект не закрывается между передачей, проверкой и публикацией.
- Итоговый файл создаётся операцией без замены существующего, включая гонку с другим процессом. Ошибка публикации сохраняет пригодный partial. Нельзя полагаться только на предварительный File.Exists.
- После успешной публикации partial удаляется; пустая служебная папка удаляется. Остановка закрывает поток и сохраняет полученные данные. Повторный запуск: та же ссылка и прежняя папка; история для этого не сохраняется.

## 4. Повторы и ошибки

| Уровень | Базовое поведение |
| --- | --- |
| Метаданные API | До 5 попыток, паузы 1, 2, 4, 8 секунд |
| Запрос ссылки скачивания | 1 попытка внутри API, повторами управляет цикл файла |
| Файл | До 20 попыток, обновление ссылки; паузы 2, 4, 8, 16, затем до 30 секунд |
| API HTTP 408, 429, 5xx | Временная ошибка, допускает повтор |
| Прочие ошибки API 4xx | Окончательная ошибка; внешний цикл не должен повторять её 20 раз |
| Нечитаемый JSON API | Окончательная ошибка |
| Обрыв соединения, сетевой таймаут | Допускается повтор; не классифицировать как постоянную ошибку диска |
| Нет места, доступа, конфликт, read-only, блокировка файла | Понятная локальная ошибка без 20 сетевых попыток |
| Отмена | Не повторять; закрыть файлы и вернуть состояние «Остановлено» |

Различать API и сервер передачи: текущий Swift помечает постоянные ошибки именно API; ответы сервера передачи обрабатывает цикл файла. Не распространять правило «все 4xx окончательные» на просроченную ссылку передачи без отдельного решения и теста обновления ссылки.

В реализации .NET заданы отдельные таймауты: API — 45 секунд на заголовки, 45 секунд бездействия каждого чтения, 90 секунд на один ответ целиком; передача — 60 секунд на заголовки, 60 секунд бездействия каждого чтения, 7 суток на одну передачу. Установка соединения ограничена 45 секундами. Общий срок включает redirects и чтение. HttpClient.Timeout отключён: лимиты обеспечивают связанные CancellationTokenSource, так как ResponseHeadersRead ограничивает область стандартного таймаута заголовками. Отмена пользователем отличается от таймаута; паузы повторов тоже отменяемы. В тестах сроки сокращены, реальные 7 суток не ожидались.

## 5. Прогресс и завершение

События движка: статус, папка результата, найденные файлы/байты, текущий файл и режим проверки, прогресс и новые сетевые байты, итоги, завершение с ошибками и числом проверок только по размеру. Интерфейс получает события независимо от сетевых операций.

Общий прогресс включает проверенные готовые файлы и текущую загрузку, но не считает чтение существующего файла сетевым трафиком. Докачанные ранее байты не повышают текущую скорость сети. После полного успеха — 100%, включая пустую папку. Частичный успех не называется полным. Оценка времени при отсутствии скорости показывает «—». Частые события ограничиваются примерно одним обновлением в 120 мс; окно не блокируется.

## 6. Приватность и сеть

Ссылка и выбранная папка хранятся только в памяти сеанса; после перезапуска ссылка пуста, назначение — системная папка «Загрузки». Нет истории, аналитики, cookies, постоянного сетевого кэша, хранилища сетевых учётных данных и автоматической отправки ошибок. Ошибки показываются в окне без отчёта на диске. Значки локальные; профили автора открываются лишь по нажатию.

API использует https://cloud-api.yandex.net. Каждый redirect API проверяется. Скачивание и каждый его redirect допускают только HTTPS-поддомены .yandex.ru / .yandex.net, без логина/пароля и с портом по умолчанию или 443. Проверка границы домена обязательна: yandex.ru.attacker.example запрещён. Стандартную проверку сертификатов не отключать. Локальный HTTP допускается только в изолированных тестах, не через пользовательские настройки.

Ограничения политики относятся к приложению: нельзя обещать отсутствие любых системных записей Windows или истории браузера. Историю системного диалога выбора папки проверить отдельно и отключить её сохранение, где это поддерживается.

## 7. Дополнения для Windows

- Предварительно выявлять недопустимые имена, зарезервированные устройства (также с расширением), управляющие символы, ADS через двоеточие, завершающие точки/пробелы, абсолютные/UNC/drive-relative пути из удалённых имён, выход через .. и совпадения без учёта регистра. Не заменять символы и не добавлять суффиксы молча. Конфликтующие элементы не скачивать; допустимые продолжать. Конфликт каталога исключает его поддерево с явной ошибкой.
- Не выбирать «победителя» по порядку API при коллизии двух имён. Конфликт должен выявляться до записи обоих объектов. Учитывать конфликт корня и служебного имени .diskloader-partials.
- Проверять containment и reparse points/junctions у служебных и целевых путей, включая существующих родителей. Защиту от подмены пути между проверкой и записью рассматривать вместе с открытием дескрипторов; одной строковой проверки недостаточно.
- При работе с одной папкой назначения блокировать одновременный запуск двух движков. Блокировка не хранит ссылку/путь в журнале, освобождается при завершении процесса и не мешает следующему запуску после сбоя.
- Проверить длинные пути, NTFS, exFAT и сетевую папку. FAT32 с файлом более 4 ГиБ должен давать понятную ошибку ограничения тома. Наличие атомарного сохранения без замены на конкретном томе подтверждается тестом; при неподдерживаемой операции сохранять partial и сообщать ошибку.
- Системную папку «Загрузки» определять через Windows Known Folders; учитывать перенаправление. При недоступности показать выбор папки, не падать.
- Закрытие окна должно дождаться корректной остановки и закрытия потоков. После принудительного завершения следующий запуск проверяет partial. Временный запрет автоматического сна снимается на всех путях завершения. Ручной сон не обещается предотвращать.

## 8. Сеанс Windows после завершения

Модель DownloadSession существует с 0.1.0-dev.3 и подключена к WPF с 0.1.0-dev.4. После полного успеха (включая пустую папку) источник очищается, итог остаётся доступным, кнопка имеет текст «Скачать» и CanStart=false до нового ввода. Программный повторный запуск с пустым полем тоже отклоняется. После отмены, частичного успеха или ошибки источник сохраняется для продолжения; новая ссылка сбрасывает режим продолжения. Пока сеанс работает, изменение ссылки и второй запуск запрещены. Всё состояние хранится только в памяти. Очистка реального поля и состояние кнопки проверены в этапе 4. macOS в этой части не меняется.

## 9. Окно и список незавершённых файлов Windows

С 0.1.0-dev.4 WPF-окно подключено к DownloadSession. Движок дополнительно передаёт FileDiscovered (удалённый путь, исходное имя, размер), FileCompleted и FileFailed. Благодаря этому одиночный путь «/» отображается настоящим именем с расширением, а после отмены известные недокачанные файлы отделяются от завершённых. Красный круг с «!» открывает таблицу имён, путей и причин. Если состав поддерева не получен, показана папка, без вымышленных имён. Список существует только в памяти и сбрасывается при новом запуске или смене назначения. Полный успех очищает видимое поле и отключает «Скачать», итог сохраняется.

Работа идёт вне UI-потока; события обрабатываются пакетами. При закрытии окна запрашивается отмена и ожидается завершение записи. Папка «Загрузки» определяется Known Folders, диалог имеет AddToRecent=false; очистка GUID состояния через ClearClientData выполняется по возможности и не является обещанием отсутствия системной истории. Запрос запрета автосна действует только во время операции. Профили автора/macOS открываются только по нажатию.

## Границы реализации

После этапа 4 есть предварительное окно приложения и настоящий тест двух небольших файлов через API Яндекса. Движок и защита также проверены на NTFS и локальном сервере; Swift-тесты не запускались. Реальные exFAT/FAT32/SMB, большие файлы и расширенная эксплуатация остаются этапом 5. Установщик, автообновление и ARM64 в этап 4 не входят. [Устройство файловой защиты](FILE-SAFETY.ru.md).
