# Результаты этапа 2 — 0.1.0-dev.2

Дата: 2026-10-30. Проверена Release-сборка независимого Plantain.Core на C# / .NET 10. Windows x64, системный build 26200, локальный том D: — NTFS, SDK 10.0.403. У проекта нет внешних NuGet-зависимостей. Пользовательского приложения пока нет.

## Автоматические проверки

**75 выполнено, 75 пройдено, 0 ошибок.** Запуск: [test.ps1](../scripts/test.ps1), без Python и внешнего доступа. Используются TCP-сервер на 127.0.0.1 с портом 0 и синтетические данные; TLS-сертификат генерируется в памяти и специально не считается доверенным.

Покрыты:

- Сохранение корня, вложенных и пустых папок; одиночный файл, нулевой размер, проверка существующих файлов до передачи и повторный запуск.
- SHA-256, MD5, приоритет SHA-256, повреждение при одинаковом размере, проверка только по размеру и отдельный итог.
- Докачка, игнорирование Range, неверные Content-Range, HTTP 416, короткие и избыточные ответы, разрыв TCP, повреждённый/полный/слишком большой partial, запрет докачки без хеша.
- Обновление истёкшей ссылки передачи, пределы 5/20 попыток и расписание пауз; постоянная ошибка API не повторяется внешним циклом.
- Пагинация с total и без него, неполный список, экранирование пути, некорректный JSON и метаданные, связка API → движок → файл.
- Отмена во время передачи и паузы, отмена API, предварительная отмена проверки и отмена на границе её завершения. После остановки файл закрыт и докачка даёт точные исходные байты.
- Таймауты заголовков, бездействия чтения, общего времени передачи и ресурса API. В тестах лимиты сокращены, реальные многосуточные сроки не ожидались.
- Разрешённый redirect с сохранением Range, запрещённый домен и ограниченный цикл redirects, стандартный отказ от недоверенного TLS-сертификата.
- Отключённые cookies, учётные данные и автоматические redirects; Set-Cookie не отправляется следующим запросом. В каталоге успешной загрузки остаётся только результат.
- Появление итогового файла между скачиванием и публикацией: чужие данные и partial сохранены. Реальная sharing violation Windows не запускает сетевые повторы.
- Потоковая запись 8 МиБ: сервер намеренно не заканчивает ответ до получения клиентского прогресса. Это подтверждает начало обработки до окончания ответа, но не заменяет измерение памяти на многогигабайтном файле.
- Базовый отказ от опасных имён и совпадений регистра до записи. Полная файловая безопасность относится к этапу 3.

Компиляция проходит с TreatWarningsAsErrors=true; предупреждений и ошибок компилятора нет. Номер читается из windows/VERSION, а фактический Git-хеш и dirty пишутся скриптом в информационную версию и локальный JSON-отчёт. Отчёт не коммитится, чтобы не создавать самоссылку коммита; он появляется в windows/artifacts/test-results.json. Финальный запуск после коммита должен указывать чистую ревизию кода этого этапа.

## Ограничения доказательств

Это тесты реализации Windows, а не запуск 37 проверок Swift. Живой API Яндекса, личные ссылки и сетевые условия реального скачивания не использовались. Стандартная TLS-проверка подтверждена отрицательным локальным тестом; успешная цепочка реального сервера отдельно не проверялась.

Не проверены exFAT, FAT32, SMB, ARM64, многогигабайтные файлы, аварийное завершение процесса, состояние после перезагрузки и чистая машина без SDK. Нет WPF-окна: скорость/ETA, поля сеанса, Known Folders, диалог выбора, доступность и управление сном ещё не реализованы.

До завершения этапа 3 библиотека не защищает от одновременных движков в одном назначении и от подмены уже проверенного пути между проверкой и файловой операцией. Базовая проверка reparse points не равна защите через дескрипторы. При недопустимом имени или коллизии сейчас отклоняется вся инвентаризация; целевое продолжение допустимых поддеревьев ещё не реализовано. Проверка не даёт основания выпускать готовое приложение или установщик.
