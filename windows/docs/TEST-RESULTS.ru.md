## Этап 3 — 0.1.0-dev.3

**101/101 проверка, 0 ошибок.** Windows x64 (build 26200), NTFS, SDK 10.0.403, Release с TreatWarningsAsErrors. Состав: 75 базовых проверок, 19 файловых сценариев и 7 проверок сеанса. Источник версии — windows/VERSION; тестовый скрипт записывает реальную ревизию и dirty в локальный JSON-отчёт. Финальная проверка после коммита должна показывать чистую ревизию этого этапа.

Новые доказательства:

- Недопустимые имена (DOS-устройства, ADS, разделители, точки/пробелы, управляющие символы, компонент более 255 UTF-16 единиц) изолируются, допустимый сосед скачивается.
- Обе стороны коллизии регистра и конфликта файл/каталог пропускаются до записи; запрещённые поддеревья не обходятся. Локальный файл вместо каталога блокирует только это поддерево.
- Реальные junctions у назначения, cache и вложенной папки не дают записи во внешнее назначение. Проверена также установка reparse point на уже открытый каталог во время загрузки.
- Реальный hardlink partial на отдельный файл отклоняется до обнуления; внешние данные остаются прежними.
- Удерживаемые родители нельзя переименовать, а partial нельзя заменить между передачей и проверкой. Публикация работает по тому же проверенному дескриптору и не заменяет чужой итоговый файл.
- Второй движок блокируется, в том числе из отдельного процесса. Тестовый процесс принудительно завершается, система освобождает дескрипторы, следующий движок докачивает исходные 3 байта до полного файла. Отмена также освобождает блокировку.
- Путь длиннее 260 символов, кириллица и emoji на NTFS сохраняются корректно. Реальный read-only partial остаётся без изменений, сетевых повторов нет.
- Правило FAT32 отклоняет размер более 4 ГиБ минус 1 байт; правило exFAT его допускает. Это тест логики, не реальных томов.
- Полный успех и пустая папка очищают ссылку в DownloadSession, сохраняют результат, возвращают «Скачать» и CanStart=false. Повторный запуск с пустым источником отклоняется. Отмена/ошибка сохраняют источник; новая ссылка запускает новый сеанс. Изменение ссылки и второй запуск во время работы запрещены.

Использовались только локальные синтетические данные в windows/artifacts. Дочерний тестовый процесс не имеет окна и завершается тестом; тест не завершает чужие процессы. Созданные junctions удаляются отдельно без обхода их целей. Служебная блокировка приложения не пишет lock-файлы, ссылки и пути на диск.

**Оставшиеся ограничения:** здесь есть только NTFS; реальные exFAT/FAT32/SMB не проверены. Не проверены многогигабайтная передача, ARM64, отключение питания/перезагрузка ОС, живой API и пользовательское окно. Проверка завершения процесса не равна проверке аварии ОС. Очистка ссылки реализована в модели, а не в ещё не существующем WPF-поле. На неподдерживаемой файловой операции нет запасного копирования с заменой: показывается ошибка, пригодный partial остаётся.

Механизм и ссылки на API описаны в [файловой защите](FILE-SAFETY.ru.md). macOS-код и его тесты не менялись и не запускались.
