# Результаты проверок Windows

## Быстрый этап 5 — 0.1.0-dev.5

Подготовлена self-contained публикация Windows x64 со встроенными .NET/WPF, ZIP и SHA-256. Проверены обязательные компоненты (exe, coreclr.dll, hostfxr.dll, PresentationFramework.dll), запуск окна и фактический путь загруженного coreclr.dll внутри portable-папки. SHA-256 архива пересчитан и совпал с файлом .sha256. Для пользователя отдельная установка .NET не нужна; ZIP нужно распаковывать целиком.

Код приложения не изменялся, поэтому 101+20 проверок этапа 4 повторно ради упаковки не выполнялись. Предыдущий настоящий тест двух файлов остаётся применим к тому же коду. Чистая машина без установленной .NET отдельно не использовалась: подтверждена загрузка встроенной среды на текущей машине. Расширенная приёмка больших файлов, внешних/сетевых томов, другого DPI и экранного диктора остаётся незавершённой. Стабильный релиз и установщик не создавались.

## Этап 4 — 0.1.0-dev.4

**101/101 проверка движка и 20/20 WPF, 0 ошибок.** Windows x64 (build 26200), NTFS, SDK 10.0.403. Release без предупреждений/ошибок. Обычный .exe запущен с установленной .NET 10 Desktop Runtime. Это не автономная упаковка и не установщик.

WPF-проверки идут в STA с настоящими Dispatcher и контролами: поле и кнопка после успеха, расширения имён и одиночный файл с путём «/», одинаковые имена в разных папках, недоступное поддерево, список после отмены, исключение без списка, модальная таблица без дубликатов и с возвратом фокуса, закрытие активного окна с остановкой, повторный успех, сброс при смене назначения, связка движка и UI, байты проверки и форматирование, Known Folders, запрос сна, обе темы и компактное окно.

Визуально просмотрены рендеры главного окна и списка в обеих темах, 100% и 200% (RenderTargetBitmap). Это не изменение DPI физического монитора. Исправлены режим привязки ProgressBar, сообщение ниже прокрутки, цвета кнопок и перенос текста таблицы. Красный «!» и статус закреплены над кнопками. Есть доступные имена и live region; отдельная проверка экранным диктором ещё не проводилась.

Через computer-use проверены запуск .exe с пустым полем и отключённым «Скачать», системный диалог и выбор папки, настоящее скачивание, очистка поля, красный значок и таблица. Предварительный визуальный runner с синтетическими данными находится только в тестовом проекте и не включён в обычное приложение.

## Этап 3 — 0.1.0-dev.3

**101/101 проверка, 0 ошибок.** Windows x64 (build 26200), NTFS, SDK 10.0.403, Release с TreatWarningsAsErrors. Состав: 75 базовых проверок, 19 файловых сценариев и 7 проверок сеанса. Источник версии — windows/VERSION; тестовый скрипт записывает реальную ревизию и dirty в локальный JSON-отчёт. Финальная проверка после коммита должна показывать чистую ревизию этого этапа.

Новые доказательства:

- Недопустимые имена (DOS-устройства, ADS, разделители, точки/пробелы, управляющие символы, компонент более 255 UTF-16 единиц) изолируются, допустимый сосед скачивается.
- Обе стороны коллизии регистра и конфликта файл/каталог пропускаются до записи; запрещённые поддеревья не обходятся. Локальный файл вместо каталога блокирует только это поддерево.
- Реальные junctions у назначения, cache и вложенной папки не дают записи во внешнее назначение. Проверена также установка reparse point на уже открытый каталог во время загрузки.
- Реальный hardlink partial на отдельный файл отклоняется до обнуления; внешние данные остаются прежними.
- Удерживаемые родители нельзя переименовать, а partial нельзя заменить между передачей и проверкой. Публикация работает по тому же проверенному дескриптору и не заменяет чужой итоговый файл.
- Второй движок блокируется, в том числе из отдельного процесса. Тестовый процесс принудительно завершается, система освобождает дескрипторы, следующий движок докачивает исходные 3 байта до полного файла. Отмена также освобождает блокировку.
- Путь длиннее 260 символов, кириллица и emoji на NTFS сохраняются корректно. Реальный read-only partial остаётся без изменений, сетевых повторов нет.
- Правило FAT32 отклоняет размер более 4 ГиБ минус 1 байт; правило exFAT его допускает. Это тест логики, не реальных томов.
- Полный успех и пустая папка очищают ссылку в DownloadSession, сохраняют результат, возвращают «Скачать» и CanStart=false. Повторный запуск с пустым источником отклоняется. Отмена/ошибка сохраняют источник; новая ссылка запускает новый сеанс. Изменение ссылки и второй запуск во время работы запрещены.

Использовались только локальные синтетические данные в windows/artifacts. Дочерний тестовый процесс не имеет окна и завершается тестом; тест не завершает чужие процессы. Созданные junctions удаляются отдельно без обхода их целей. Служебная блокировка приложения не пишет lock-файлы, ссылки и пути на диск.

**Оставшиеся ограничения:** здесь есть только NTFS; реальные exFAT/FAT32/SMB не проверены. Не проверены многогигабайтная передача, ARM64, отключение питания/перезагрузка ОС, живой API и пользовательское окно. Проверка завершения процесса не равна проверке аварии ОС. Очистка ссылки реализована в модели, а не в ещё не существующем WPF-поле. На неподдерживаемой файловой операции нет запасного копирования с заменой: показывается ошибка, пригодный partial остаётся.

Механизм и ссылки на API описаны в [файловой защите](FILE-SAFETY.ru.md). macOS-код и его тесты не менялись и не запускались.

## Архив: этап 2 — 0.1.0-dev.2

Дата: 2026-10-30. Проверена Release-сборка независимого Plantain.Core на C# / .NET 10. Windows x64, системный build 26200, локальный том D: — NTFS, SDK 10.0.403. У проекта нет внешних NuGet-зависимостей. Пользовательского приложения пока нет.

### Автоматические проверки этапа 2

**75 выполнено, 75 пройдено, 0 ошибок.** Запуск: [test.ps1](../scripts/test.ps1), без Python и внешнего доступа. Используются TCP-сервер на 127.0.0.1 с портом 0 и синтетические данные; TLS-сертификат генерируется в памяти и специально не считается доверенным.

Покрыты:

- Сохранение корня, вложенных и пустых папок; одиночный файл, нулевой размер, проверка существующих файлов до передачи и повторный запуск.
- SHA-256, MD5, приоритет SHA-256, повреждение при одинаковом размере, проверка только по размеру и отдельный итог.
- Докачка, игнорирование Range, неверные Content-Range, HTTP 416, короткие и избыточные ответы, разрыв TCP, повреждённый/полный/слишком большой partial, запрет докачки без хеша.
- Обновление истёкшей ссылки передачи, пределы 5/20 попыток и расписание пауз; постоянная ошибка API не повторяется внешним циклом.
- Пагинация с total и без него, неполный список, экранирование пути, некорректный JSON и метаданные, связка API → движок → файл.
- Отмена во время передачи и паузы, отмена API, предварительная отмена проверки и отмена на границе её завершения. После остановки файл закрыт и докачка даёт точные исходные байты.
- Таймауты заголовков, бездействия чтения, общего времени передачи и ресурса API. В тестах лимиты сокращены, реальные многосуточные сроки не ожидались.
- Разрешённый redirect с сохранением Range, запрещённый домен и ограниченный цикл redirects, стандартный отказ от недоверенного TLS-сертификата.
- Отключённые cookies, учётные данные и автоматические redirects; Set-Cookie не отправляется следующим запросом. В каталоге успешной загрузки остаётся только результат.
- Появление итогового файла между скачиванием и публикацией: чужие данные и partial сохранены. Реальная sharing violation Windows не запускает сетевые повторы.
- Потоковая запись 8 МиБ: сервер намеренно не заканчивает ответ до получения клиентского прогресса. Это подтверждает начало обработки до окончания ответа, но не заменяет измерение памяти на многогигабайтном файле.
- Базовый отказ от опасных имён и совпадений регистра до записи. Полная файловая безопасность относится к этапу 3.

Компиляция проходит с TreatWarningsAsErrors=true; предупреждений и ошибок компилятора нет. Номер читается из windows/VERSION, а фактический Git-хеш и dirty пишутся скриптом в информационную версию и локальный JSON-отчёт. Отчёт не коммитится, чтобы не создавать самоссылку коммита; он появляется в windows/artifacts/test-results.json. Финальный запуск после коммита должен указывать чистую ревизию кода этого этапа.

### Ограничения доказательств этапа 2

Это тесты реализации Windows, а не запуск 37 проверок Swift. Живой API Яндекса, личные ссылки и сетевые условия реального скачивания не использовались. Стандартная TLS-проверка подтверждена отрицательным локальным тестом; успешная цепочка реального сервера отдельно не проверялась.

Не проверены exFAT, FAT32, SMB, ARM64, многогигабайтные файлы, аварийное завершение процесса, состояние после перезагрузки и чистая машина без SDK. Нет WPF-окна: скорость/ETA, поля сеанса, Known Folders, диалог выбора, доступность и управление сном ещё не реализованы.

До завершения этапа 3 библиотека не защищает от одновременных движков в одном назначении и от подмены уже проверенного пути между проверкой и файловой операцией. Базовая проверка reparse points не равна защите через дескрипторы. При недопустимом имени или коллизии сейчас отклоняется вся инвентаризация; целевое продолжение допустимых поддеревьев ещё не реализовано. Проверка не даёт основания выпускать готовое приложение или установщик.
