# Подорожник для Windows

Подорожник — скачает, когда Диск не может.

**Windows: 0.1.0-dev.3. Этап 3: файловая защита и поведение сеанса.**

Реализована библиотека загрузчика на C# / .NET 10, без внешних пакетов. На Windows x64 прошла 101 автоматическая проверка. Пользовательского окна, готового portable-приложения и установщика ещё нет. Это предварительная разработка, не публичный выпуск.

Есть готовая [версия для macOS](https://github.com/sirdimitry/plantain/blob/main/README.md), сейчас 1.1.1. [Скачать macOS DMG](https://github.com/sirdimitry/plantain/releases/tag/v1.1.1). Код macOS находится в `main`; Windows разрабатывается в отдельной ветке `windows` того же репозитория.

## Что готово

- Изучено поведение macOS 1.1.1, исходная точка `acb34baa815265967a81fd6e5a14d2271a5ec5e3`.
- Зафиксированы [требования к загрузчику и отличия Windows](docs/BEHAVIOR.ru.md).
- Составлена [матрица проверок и условия готовности](docs/ACCEPTANCE.ru.md).
- Заданы [порядок следующих этапов и правила версий](docs/DEVELOPMENT.ru.md).
- Реализованы API и пагинация, потоковая передача, SHA-256/MD5, проверка имеющихся файлов, докачка, отмена и ограниченные повторы.
- Добавлены события прогресса для будущего интерфейса, сохранение без перезаписи и раздельные таймауты заголовков, чтения и ресурса целиком.
- Сеть использует HTTPS и обычную проверку TLS; проверяется каждый redirect, cookies и сетевые учётные данные отключены. Логи и история источников не записываются.
- Защищённые операции с файлами через дескрипторы Windows: удержание родителей, открытие потомков относительно каталога, запрет обхода reparse points/junctions, проверка жёстких ссылок partial, публикация проверенного объекта без замены.
- Блокировка одновременных загрузок в одну папку, автоматически снимаемая системой при завершении процесса; отдельного lock-файла нет.
- Конфликтующие и недопустимые имена пропускаются с ошибкой; остальные файлы продолжают скачиваться. Конфликт каталога исключает его поддерево.
- Модель сеанса после полного успеха очищает ссылку, сохраняет итог и переключает кнопку на неактивное «Скачать». При остановке или ошибках ссылка остаётся для продолжения. Готового окна ещё нет; его привязка к модели — этап 4.

## План реализации

Целевая первая платформа — Windows 11 x64. Стек — C# / .NET 10 LTS, будущий интерфейс — WPF. Далее: интерфейс, проверка реальной эксплуатации и других файловых систем, portable-сборка с включённой средой .NET. ARM64 требует отдельной проверки. Установщик будет отдельным этапом позже.

## Проверка из исходников

Нужен .NET 10 SDK; Python и сторонние тестовые пакеты не требуются. Из корня репозитория в PowerShell:

```powershell
.\windows\scripts\test.ps1
```

Скрипт использует локальный SDK из `windows/.tools/dotnet`, если он есть, иначе установленный `dotnet`. SDK не входит в репозиторий и автоматически тестовым скриптом не устанавливается. Можно передать `-Dotnet 'путь\dotnet.exe'`.

Проверки используют собственный HTTP/TLS-сервер на случайном локальном порту и синтетические данные. Временные файлы и JSON-отчёт находятся в `windows/artifacts`. Отчёт `test-results.json` содержит версию, Git-коммит и пометку `dirty` при локальных изменениях. SDK, результаты сборок и отчёты исключены из Git.

Сборка библиотеки установленным SDK:

```powershell
dotnet build .\windows\src\Plantain.Core\Plantain.Core.csproj -c Release
```

Версия читается из [VERSION](VERSION). При прямой сборке без тестового скрипта Git-ревизия обозначается `unknown`. Тесты запускаются через `test.ps1`, а не `dotnet test`: это автономный исполняемый набор с ненулевым кодом выхода при ошибке. Не следует запускать macOS-скрипты из корня для сборки Windows.

## Проверки на этом этапе

101/101 проверка прошла на Windows x64, NTFS, SDK 10.0.403: базовые сценарии загрузки, реальные junctions/hardlinks, удержание каталогов и partial, конфликтные имена, длинный Unicode-путь, блокировка между процессами, восстановление после принудительного завершения и очистка ссылки после успеха. [Подробные результаты и ограничения](docs/TEST-RESULTS.ru.md).

Живой API Яндекса и личные ссылки не использовались. Многогигабайтные файлы, реальные exFAT/FAT32/SMB, ARM64, перезагрузка ОС и пользовательский интерфейс ещё не проверены. Ограничение FAT32 проверено как правило, а не на реальном томе. 37 проверок Swift не запускались и не считаются проверками Windows.

Следующий этап — WPF-интерфейс. Защищённый файловый слой предназначен для Windows и требует поддержки используемых операций файловой системой. Если операция не поддерживается, загрузка сообщает ошибку и сохраняет пригодный partial, без перехода к небезопасному копированию/перезаписи. Совместимость с внешними и сетевыми томами ещё предстоит подтвердить.

## Приватность и ограничения

Библиотека не сохраняет ссылки и выбранные пути в настройки или отчёты, не отправляет аналитику. На диске остаются результаты и `.diskloader-partials`, имя partial основано только на размере и хешах. Без хеша partial обнуляется перед новой попыткой. Блокировка назначения хранится в открытом дескрипторе, без журнала и постоянного маркера. Отчёт тестов создаётся разработчиком и содержит синтетические сценарии, не историю пользовательских загрузок. Очистка ссылки после успеха проверена в модели; отображение поля и историю системного диалога предстоит проверить в UI. Системная диагностика Windows не контролируется приложением. Несовместимые имена отклоняются без скрытого переименования и перезаписи.
